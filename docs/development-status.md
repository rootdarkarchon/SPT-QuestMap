## SPT 4.0.13 integration audit

- **Source/runtime match:** supplied source `Build.props` declares `4.0.13` and its Git commit is `2891fd41fd07b6150a2192ac0d24adb93eb72862`. Installed `SPT.Server.dll`, `SPTarkov.Server.Core.dll`, `SPTarkov.Server.Web.dll`, `SPTarkov.Common.dll`, and `SPTarkov.DI.dll` all report `4.0.13.0` and product version `4.0.13-RELEASE+2891fd4.20260302.2891fd41fd07b6150a2192ac0d24adb93eb72862`.
- **Mod identity:** one top-level DLL under `user/mods/<mod>/` must contain exactly one `AbstractModMetadata` implementation. `IModWebMetadata` is the marker that enrolls that mod in SPT web integration. `SptVersion` will be constrained to exact `4.0.13`.
- **Dependency injection/lifecycle:** SPT scans validated mod assemblies through `DependencyInjectionHandler.AddInjectableTypesFromAssemblies`. Mod services can use `[Injectable]`; `IOnLoad` is the normal startup hook. `IOnWebAppBuildModAsync` exists for Kestrel-build configuration but is not needed for ordinary MVC/static registration.
- **Configuration access:** `ConfigServer` is the sole injectable config owner in 4.0.13. Its constructor loads `SPT_Data/configs/*.json[c]` into a static dictionary, and all seven in-tree `QuestConfig` consumers retrieve the record with `ConfigServer.GetConfig<QuestConfig>()`. `QuestConfig` has no `[Injectable]` attribute, while the obsolete message only announces the planned 4.1 direct-injection replacement. QuestMap does not need to retrieve the record itself: its required faction and event classification are exposed by `QuestHelper.QuestIsForOtherSide` and `SeasonalEventService.IsQuestRelatedToEvent`, which read the same config internally.
- **Blazor/page/assets:** `SPTWeb.InitializeSptBlazor` adds each web-mod assembly as an MVC/Razor application part and enables Interactive Server components. `SPTWeb.UseSptBlazor` adds web-mod assemblies to the Blazor router but maps only a physical mod `wwwroot` at `/<assembly-name>/`. QuestMap owns `/questmap` through `QuestMap.razor`; its CSS and Canvas module are embedded in the DLL, emitted/imported by the Razor page, and require no QuestMap static-file route. `ModValidator.ValidMod` recursively rejects deployed `.js` and `.ts` files.
- **Authentication boundary:** 4.0.13 registers no ASP.NET authentication/authorization service or policy for its MVC/Blazor pages. `HttpServer` reads `PHPSESSID` for SPT listeners, but a normal browser visit does not acquire that cookie. At the user's explicit direction, `/questmap` does not require authentication. QuestMap now exposes no JSON data controller; sanitized snapshots reach the browser only through its Interactive Server circuit. The installed server is currently bound to `127.0.0.1:6969`; changing that bind address would expose the page to reachable clients.
- **Profiles:** singleton `SaveServer.GetProfiles()` returns all successfully loaded `SptProfile` entries; invalid/unloadable entries can be rejected with `IsProfileInvalidOrUnloadable`. Sanitized selector fields come from the dictionary key plus `CharacterData.PmcData.Info` (`Nickname`, `Side`, `Level`) only.
- **Quest topology/data:** singleton `DatabaseService.GetQuests()` returns the live, post-mod database dictionary. `DatabaseService.GetLocales().Languages` and `.Global` expose the installed client-language set; `LocaleService.GetLocaleDb(language)` is the authoritative localized game dictionary with SPT's English fallback. `Quest.Location` is `any` or a location Mongo ID, and its display name is the locale key `<locationId> Name`; loaded map metadata is available from `DatabaseService.GetLocations()`. `Quest.Conditions.AvailableForStart` exposes `Quest`, `Level`, `TraderLoyalty`, and `TraderStanding` gates; `QuestCondition` carries `index`, `parentId`, `visibilityConditions`, `target`, `status`, `compareMethod`, `value`, and `availableAfter`.
- **Authoritative availability:** `QuestHelper.GetClientQuests(sessionId)` is SPT's profile-aware visible/available result and stamps `Quest.SptStatus`. Local graph derivation will explain locked reasons and future nodes without contradicting that result. `QuestHelper.QuestIsForOtherSide` and `ShowEventQuestToPlayer` are public authoritative applicability checks.
- **Quest/profile status:** exact `QuestStatusEnum` values are `Locked`, `AvailableForStart`, `Started`, `AvailableForFinish`, `Success`, `Fail`, `FailRestartable`, `MarkedAsFailed`, `Expired`, and `AvailableAfter`. Profile entries are `PmcData.Quests`; objective completion IDs are `QuestStatus.CompletedConditions`; counters are `PmcData.TaskConditionCounters` (`id`, `type`, `value`, `sourceId`).
- **Seasonal filtering:** `SeasonalEventService.IsQuestRelatedToEvent`, `ChristmasEventEnabled`, `HalloweenEventEnabled`, and `GetActiveEvents` are authoritative. `IsQuestRelatedToEvent` is the public accessor over `QuestConfig.EventQuests`; topology checks every 4.0.13 `SeasonalEventType` value instead of reading the config directly. `ShowNonSeasonalEventQuests` is false in this install. The topology layer must additionally remove descendants whose only prerequisite ancestry is through excluded `None` quests, per product requirements.
- **Faction/game edition:** `QuestConfig.UsecOnlyQuests` and `BearOnlyQuests` back `QuestHelper.QuestIsForOtherSide`. `QuestHelper.GetClientQuests` also applies profile-edition filters; future-node derivation will preserve the selected profile's `Info.GameVersion` behavior where source exposes it.
- **Traders:** `DatabaseService.GetTraders()` provides `Trader.Base` (`Nickname`, `Avatar`, `UnlockedByDefault`, loyalty thresholds). Profile truth is `PmcData.TradersInfo[traderId]` (`Unlocked`, `Disabled`, `LoyaltyLevel`, `Standing`, `SalesSum`).
- **Existing image routes:** `DatabaseImporter` maps every file in `SPT_Data/images` to its extension-insensitive `/files/<relative-path>` route through `ImageRouter`. Quest `image` values already use `/files/quest/icon/...`; trader `Base.Avatar` values already use `/files/trader/avatar/...`. No artwork copying or proxy endpoint is required.
- **Build/deployment:** build against the matching installed net9.0 assemblies with `Private=false`. SPT loads the top-level DLL from `SPT/user/mods/<mod>/`; QuestMap's locale, CSS, and renderer resources are contained in that DLL. Build/test output stages a clean DLL/PDB-only `dist/` tree before deployment. DLL hashes must be compared before copy/restart.
